폰트 점검 시스템

기여도 100%

WHY?

인쇄 작업에 사용하는 폰트는 PC에 설치되어 있어도 상업 인쇄나 고객에게 납품하는 PDF에 포함할 수 있는 범위가 다릅니다. 킨코스코리아에서 공급사 자료와 회사의 승인 기준을 대조하는 과정과, 작업자의 PC에 어떤 폰트가 깔렸는지 확인하는 과정을 연결했습니다.

WHAT?

  • 설치 폰트 확인

    브라우저에서 접근을 허용하면 설치 폰트를 읽어 패밀리 단위로 표시하고, 펼쳐서 스타일과 개별 폰트 이름을 확인할 수 있습니다.

  • 승인 기준 대조

    설치 폰트가 현재 승인 목록에 있는지 비교해 ‘정상’과 ‘확인 필요’를 구분합니다. 확인이 필요한 항목부터 열어볼 수 있습니다.

  • 라이선스 검토와 기록

    공급사의 공식 자료에서 상업 인쇄와 PDF 포함 조건을 용도별로 검토해 기준을 관리합니다. 이전 점검은 전체 수와 확인 필요 수, 상세 목록을 다시 볼 수 있습니다.

HOW?

구현 과정

Chromium의 Local Font Access API인 window.queryLocalFonts()로 전체 이름, 패밀리, 스타일, PostScript 이름을 가져옵니다. 화면은 패밀리로 묶어 보여주고, 판정에는 네 값을 모두 사용해 개별 스타일을 확인합니다.

Next.js 화면에서 서버의 승인 기준과 버전을 불러온 뒤, 수집한 정보와 승인 목록이 정확히 일치하는지 확인합니다. 공식 라이선스 문서의 인쇄·PDF 사용 조건은 승인 기준을 마련하고 미확인 항목을 후속으로 검토하는 데 사용했습니다.

점검 중 브라우저 권한이 없거나 기준표가 준비되지 않은 상태는 결과 화면에서 구분합니다. 설치 목록을 읽었다는 사실과 승인 기준 비교가 끝났다는 사실을 별도로 처리했습니다.

문제와 해결

  1. 비슷한 폰트 이름이 같은 폰트로 보일 수 있는 경우

    패밀리 이름만으로 승인하지 않고 전체 이름, 패밀리, 스타일, PostScript 이름이 승인 목록의 한 항목과 모두 일치하는지 비교했습니다. 목록을 패밀리로 묶어도 판정은 스타일별로 남겼습니다.

  2. 승인 자료가 부족하거나 기준표를 읽지 못하는 경우

    공식 자료가 불충분하거나 사용 조건이 충돌하는 폰트는 검토 대상으로 남겼습니다. 기준표가 아직 없거나 형식이 맞지 않으면 비교 자체를 미완료로 처리해 점검이 끝났다는 오해를 줄였습니다.

  3. 권한 거부와 설치 폰트 0개를 구분하기 어려운 경우

    브라우저 미지원, 접근 거부, 정상 수집 후 빈 목록을 나눠 처리했습니다. 작업자는 자신의 브라우저나 권한을 먼저 확인해야 하는지 알 수 있습니다.

결과

사용자가 웹에서 설치 폰트를 조회하고 승인 목록과 비교해 추가 검토가 필요한 항목을 찾을 수 있게 했습니다. 용도별 라이선스 확인 자료와 점검 이력을 함께 활용해 상업 인쇄와 PDF 납품 전에 살펴볼 폰트를 좁힐 수 있습니다.
