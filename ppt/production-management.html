생산관리 시스템

WHY?

인쇄 접수에서는 소재·규격·수량·파일과 고객이 원하는 날짜를 먼저 받습니다. 이후 제작 담당자가 파일과 사양을 검토해야 제작 가능한 조건과 확정 납기를 정할 수 있습니다. 접수 정보와 제작 검토 내용을 한 건에서 이어서 처리할 수 있도록 킨코스코리아의 생산관리 시스템을 개발하고 있습니다.

HOW?

구현 과정

Next.js 접수 화면을 센터·거래처 선택, 품목 입력, 파일 연결 단계로 나눴습니다. 품목과 파일을 각각 관리하고 검토 화면에서 둘을 함께 보여줍니다. 출력 방식처럼 제작에 필요한 항목은 신규 접수에서 확인하고, 필수값이 없으면 저장 전에 입력을 안내합니다.

FastAPI에서 받는 접수 정보에는 고객 요청 납기와 검토 후 확정하는 납기를 별도 항목으로 두었습니다. 접수 저장과 생산 제출도 단계로 나눠, 생산 제출이 완료되지 않은 건은 기존 접수 내역에서 다시 열 수 있게 구성했습니다.

반복 주문은 과거 사양을 새 초안에 복사한 뒤 현재 입력과 다시 조합합니다. 주문을 받을 때의 단가와 새로 올린 파일의 페이지 수로 견적을 계산하고, 작업 단위로 접수·검토 상태를 보여주도록 했습니다.

WHAT?

  • 작업 접수

    접수 센터와 거래처를 선택하고 출력 방식, 소재, 규격, 수량, 후가공, 수령·배송 정보를 품목 단위로 입력합니다.

  • 파일 배정과 검토

    올린 파일을 품목에 연결하고 PDF 미리보기에서 제작에 사용할 파일을 확인합니다. 제작 담당자가 같은 접수 내역에서 품목 사양과 첨부파일을 비교할 수 있습니다.

  • 반복 주문과 견적

    과거 작업 사양을 새 접수에 불러오고, 새 파일의 페이지 수와 현재 단가를 적용합니다. 입력 중인 수령일과 배송정보를 유지합니다.

  • 접수·생산 상태 조회

    저장된 접수에서 필요한 작업을 골라 상세 정보를 확인합니다. 접수 검토와 생산 대기 목록을 기준으로 다음 단계에 넘길 업무를 조회할 수 있도록 개발 중입니다.

현재 진행 상황

현업 요구사항을 바탕으로 필수 접수 항목, 납기 관리 기준, 공정 진행 상태를 정의했습니다. 작업 접수에서 제작·출고까지 추적하는 기능을 개발 중입니다.

문제 해결

  1. 접수는 저장됐지만 생산 제출만 실패하는 경우

    저장과 제출 결과를 따로 기록하도록 했습니다. 접수 ID가 이미 있는 건은 파일과 사양을 다시 확인한 뒤 같은 ID로 생산 제출만 재시도합니다. 처음부터 다시 작성할 때 발생하는 중복 접수를 줄이는 방식입니다.

  2. 과거 작업을 불러오면 오늘 입력한 내용이 덮이는 경우

    다시 쓸 품목 사양과 오늘 접수에서 결정한 수령·배송 정보를 구분했습니다. 과거 출력 방식과 소재는 초안으로 가져오고, 새 파일의 페이지 수와 현행 단가로 견적을 다시 계산합니다.

  3. 과거 기록에 출력 방식이 비어 있는 경우

    기존 내역의 빈값을 그대로 표시해 임의의 출력 방식이 붙는 일을 막았습니다. 신규 작업에는 출력 방식을 필수로 확인해 같은 누락이 반복되지 않게 했습니다.

  4. 요청일과 제작 가능일이 다른 경우

    문의 시점의 요청일과 검토 후 확정 납기를 함께 관리하도록 설계했습니다. 마감시간 이후 접수와 대량 작업의 예외 조건도 납기 요구사항에 반영했습니다.
