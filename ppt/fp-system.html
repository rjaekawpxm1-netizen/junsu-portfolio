WHY?

씨에이에스에서 제안 견적을 낼 때는 긴 제안요청서를 읽고, 필요한 개발 기능을 나눈 다음 기능점수와 비용을 직접 계산했습니다. 첫 산정까지 시간이 걸렸고, 담당자마다 기능을 분류하는 기준과 보정 방식이 달라질 수 있었습니다. 문서 검토에서 산정 초안까지 이어지는 시스템을 단독으로 기획하고 개발했습니다.

WHAT?

  • 제안 문서에서 기능 추출

    제안요청서나 기능정의서에서 개발 대상 기능 후보를 찾아 검토 목록으로 정리합니다.

  • 사업 유형별 산정

    기능점수(FP)와 사업 유형에 맞는 단가를 적용해 신규 개발·유지보수·재구축 비용의 초안을 확인합니다.

  • 검토·보정·내보내기

    담당자가 추출된 기능을 수정한 뒤 다시 산정할 수 있습니다. 수정한 산정 내역을 저장하거나 Excel로 내려받을 수 있습니다.

HOW?

구현 과정

제안 문서에서 텍스트를 추출하고 Claude API에는 기능 후보의 분류와 정리를 맡겼습니다. 정리된 기능 목록을 별도 계산 로직에 넘긴 다음, 공통 기능점수 기준과 사업 유형별 단가를 적용해 결과를 계산합니다.

React 화면에서 AI가 추출한 기능 목록과 산정 결과를 연결했습니다. 담당자가 빠졌거나 잘못 분류된 기능을 수정하면 보정 내용을 반영해 다시 계산합니다. 확정할 산정 내역은 Supabase에 저장하거나 Excel로 내보냅니다.

문제와 해결

  1. 같은 문서에서도 기능 범위와 점수가 달라지는 경우

    문서에서 기능을 찾는 기준을 명시하고, 수치 계산과 보정은 공통 규칙으로 분리했습니다. 담당자는 산정 초안에서 기능 누락이나 범위 차이를 먼저 확인할 수 있습니다.

  2. AI가 문서에 없는 기능이나 틀린 숫자를 제안하는 경우

    추출 결과를 바로 최종 비용으로 사용하지 않고 별도 검증·계산 단계를 거치게 했습니다. 화면에서는 먼저 기능 목록을 확인하고 조정한 뒤 계산 결과를 다시 볼 수 있습니다.

  3. 긴 문서를 읽는 도중 AI 호출이 끊기는 경우

    분석 요청이 중단됐을 때 재시도할 수 있게 했습니다. 결과가 완성되지 않은 상태에서 불완전한 산정값을 그대로 활용하는 일을 줄이려는 처리입니다.

결과

약 2주가 걸리던 수작업에서, 문서를 올리고 약 5분 내 초기 산정 결과를 확인하는 흐름으로 개선했습니다. 담당자는 초안에서 보정이 필요한 항목을 검토하고, 결과를 Excel로 활용할 수 있습니다. 전사 실운영에 적용했습니다.
