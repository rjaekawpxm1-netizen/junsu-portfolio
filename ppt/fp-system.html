FP 산정 AI 시스템

실무 · 씨에이에스 · 단독 기획·개발

제안요청서에서 개발 기능을 추출하고, 기능점수와 개발비의 초기 산정 결과를 만드는 사내 시스템입니다. 기획부터 화면, 문서 분석, 계산 기준 검증까지 담당했습니다.

GitHub Repository ↗

왜 만들었나

사업 제안 견적을 내려면 담당자가 긴 제안요청서를 읽고, 어떤 기능이 필요한지 나눈 뒤, 기능별로 점수를 매겨 비용을 계산해야 했습니다. 초도 산정에 약 2주가 걸렸고, 같은 문서를 읽어도 기능을 나누는 기준이 담당자마다 달라질 수 있었습니다.

문서 속 요구사항을 찾는 반복 작업을 줄이고, 누구나 같은 산정 기준을 적용해 초안을 검토할 수 있도록 만들었습니다.

주요 기능

  • 제안요청서와 기능정의서의 내용을 읽어 검토할 기능 목록을 정리합니다.
  • 기능점수(FP)와 개발비를 산정하고, 신규 개발·유지보수·재구축 유형에 맞는 결과를 확인할 수 있습니다.
  • 사용자가 기능 목록과 산정 결과를 검토해 보정하고, 저장하거나 Excel로 내보낼 수 있습니다.

어떻게 구현했나

제안요청서의 텍스트를 추출한 뒤 Claude API로 기능 후보를 분류합니다. 기능 후보가 정리되면 별도 계산 로직에 기능점수 기준과 사업 유형별 단가를 적용해 점수와 개발비를 산정합니다.

React 화면에서 사용자가 기능 목록을 수정해 다시 계산할 수 있게 했습니다. 산정 내역은 Supabase에 저장하거나 Excel로 내려받을 수 있습니다.

문제와 해결

  1. 같은 문서에서 기능을 나누는 기준이 달라지는 문제

    AI에 같은 기준으로 기능을 추출하도록 지시하고, 산정 단계에서는 공통 계산 규칙을 적용했습니다. 계산과 보정은 문서 해석부와 분리해 각각 확인할 수 있게 했습니다.

  2. AI가 문서에 없는 기능이나 잘못된 숫자를 제시하는 문제

    AI가 제시한 수치를 그대로 쓰지 않고 별도 계산·검증 단계에서 확인했습니다. 문서가 길거나 AI 호출이 중단될 때는 재시도할 수 있게 했습니다.

결과

약 2주가 걸리던 수작업에서, 문서를 올리고 약 5분 내 초기 산정 결과를 확인하는 흐름으로 개선했습니다. 담당자는 초안에서 보정이 필요한 항목을 검토하고, 결과를 Excel로 활용할 수 있습니다. 전사 실운영에 적용했습니다.
